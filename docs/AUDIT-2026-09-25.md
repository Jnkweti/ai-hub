# AI Hub audit and remediation — September 25, 2026

Scope: AI Hub's C# core, WPF screens and controls, agent transports, shared status workflow, local persistence, process lifecycle, build/shortcut scripts, package dependencies, and installed-app update path. Findings below are ordered by practical impact. Priorities describe this local application; they are not CVSS scores or claims of demonstrated remote exploitation.

The three-way conversation fix is implemented. Both agents now share an ordered transcript, and only one works at a time. An explicit address selects the first speaker; otherwise the recent speaker/handoff supplies continuity. A new room defaults to Codex. The peer receives the completed first reply and inline human answers before contributing. Persisted cursors avoid resending already shared messages within the bounded recent context. Agents can hand off, pass, or wait for the user. The host still enforces cancellation and the collaboration limit.

## Findings, root causes, and corrections

| Priority | Finding and root cause | Implemented correction | Evidence |
| --- | --- | --- | --- |
| High | Conversation loss across app instances: separate windows independently loaded and rewrote the complete rooms file every four seconds. Atomic file replacement alone did not prevent stale writers. | Acquire an OS-backed exclusive instance lease before loading data; a second launch activates the existing owner and exits. Crashes release the handle. Separate test profiles remain independent. | Real second-process exclusion/crash-recovery test; native second-launch and restart checks. |
| High | Duplicate answers and work: discussion mode broadcast the same initial assignment to both providers before either saw the other's result. Editing mode serialized but always started Codex. | One speaker at a time in both modes; explicit address and recent-speaker/handoff routing; updated peer context; per-session delivery cursors; question/pass guards checked before the next turn. | Conversation regression tests and sequential native input/permission tests. |
| High, conditional | Unexpected executable selection: empty/relative PATH entries could resolve an executable from the working directory; host Git and Notepad launches used bare names. This matters when discovery falls through to those locations. | Ignore empty/relative PATH entries; launch discovered tools, Git, and system Notepad using absolute paths. Explicitly configured tools remain user-trusted executables. | Executable-discovery test with a fake project-local executable and a relative PATH. No arbitrary code was executed by the test. |
| High, maintenance | The framework-dependent app used the laptop's .NET 10.0.3 runtime, leaving app security fixes dependent on machine updates. | Publish a self-contained Windows x64 package with .NET/Windows Desktop 10.0.12; pin that version in the build script and verify the runtime's Microsoft signature. | Packaged runtimeconfig and signed coreclr.dll; native suite on the bundle. |
| Medium | A delayed old pause/failure could clear the shared client collection or publish stale state after Stop timed out and a replacement run began. Cleanup used live shared ownership after an await. | Detach each run's clients before awaiting disposal; serialize registration/detachment and invalidate old callbacks immediately; publish terminal state only for the matching generation. | Regression deliberately delays old cleanup beyond Stop's wait, starts a replacement, and verifies that new state/client ownership survive. |
| Medium | Valid JSON with null lists, null records, unsafe/duplicate IDs, or invalid nested input/context data could crash startup. Only JSON syntax errors were handled. | Normalize recoverable fields/records and IDs, validate settings/enums, and retain an untouched uniquely named backup before saving repaired data. Report recovery in the UI. | Malformed-record, idempotence and backup-content tests; native startup/restart with damaged records. |
| Medium | Duplicate input-request IDs threw outside the adapter's try/catch, potentially leaving the provider turn and original question waiting. Very large choices or request bursts could allocate excessive controls. | Register inside the guarded handler, fail the turn and cancel original requests on protocol errors; bound pending requests to 16, choices to 64, and option text lengths. | Both real-pipe provider fixtures exercise duplicates and floods; invalid-choice parsing test. |
| Medium | Unbounded line reads, accumulated text and recursive rich-text rendering could exhaust memory or freeze the UI on malformed/oversized output. Repeated process disposal could also throw. | Bound CLI frames and streamed replies to 4,194,304 characters; observe reader failures, fail pending RPCs, and make disposal idempotent. Limit visible Markdown to 100,000 characters, depth 32 and 5,000 rich-text nodes, falling back to plain text for excessive complexity. Full accepted messages remain copyable/exportable. | Unterminated oversized stdout/stderr, malformed JSON, repeated/failed-launch disposal tests; native long-message preview with full saved content preserved. |
| Medium | Predictable `.tmp` names could collide or follow an existing link; generic data filenames lacked a path boundary. | Create unique temporary files exclusively, flush before atomic replacement, validate filenames, and reject linked data/activity targets. | Existing temp sentinel, traversal rejection, locked-destination rollback and temporary-file cleanup tests. |
| Medium | Export and activity writes did not consistently catch IO/access-denied errors, allowing a read-only destination or log to crash UI callbacks. | Surface export/save/log failures in the status label and preserve app responsiveness; use the system Notepad path when opening logs. | Native read-only log fixture finishes its turn without changing the sentinel; export handler source review. |
| Medium | The fallback project walker recursively traversed unlimited empty directories, while Git output capture was unbounded. File-count limits did not protect empty/deep trees. | Iterative traversal, maximum depth 64 and 50,000 entries, bounded Git output, explicit incomplete-scope notices, and no freshness reuse for incomplete coverage. | Deep-empty-tree regression plus existing Git/content/cache/scope-validation tests. |
| Low | Tool version checks left an unused redirected stream task unobserved and allowed unbounded capture. | Drain both streams with bounded capture, observe both tasks, cancel on failure, and terminate the owned child on exit/timeout. | Build and settings workflow checks; source review of both output paths. |

Microsoft's [September servicing release](https://devblogs.microsoft.com/dotnet/dotnet-and-dotnet-framework-september-2026-servicing-updates/) and [.NET 10 downloads](https://dotnet.microsoft.com/en-us/download/dotnet/10.0) identify the reviewed 10.0.12 patch. A future self-contained runtime update requires rebuilding/reinstalling AI Hub.

## Verification

- Core/protocol suite: **87 passed**. These include actual subprocess pipes, malformed/oversized input, crash release, cancellation races, persistence failure, shared-context ordering, status cache validation, loop guards and input handling. See `artifacts/audit-core-results.txt`.
- Native WPF suites: appearance, keyboard guard, usability, navigation, mission control, conversation management, project status, activity, inline input, and the new audit recovery/resource-limit checks. Tests use isolated data directories and fixture providers; they do not read or edit the user's chosen project through a model.
- After the final lifecycle/input hardening, the affected audit, mission-control, conversation-management and inline-input suites passed again. Results are recorded in `artifacts/audit-final-desktop-results.txt`; the broad pass is recorded in `artifacts/audit-desktop-results.txt`.
- The NuGet direct/transitive advisory scan returned no known vulnerable packages. See `artifacts/audit-dependency-scan.json`. This is advisory coverage, not a guarantee of vulnerability-free code.
- Runtime verification: bundled .NETCore.App and WindowsDesktop.App are 10.0.12; coreclr.dll's Authenticode signature verifies as Microsoft Corporation/.NET.
- Version 0.5.0 is installed and open. Installed files match candidate SHA-256 hashes, conversation content/drafts/native sessions are preserved, and the taskbar shortcut's bytes and target are unchanged. The running process loaded `app/coreclr.dll` from its signed 10.0.12 bundle. App/data backups and exact installation evidence are recorded in `docs/VERIFICATION.md` and `artifacts/audit-install-result.json`.

These checks establish local host behavior and regression coverage. No live model call or external penetration test was performed for this audit. Provider protocol fixtures exercise the expected installed integration; future CLI/protocol changes still need compatibility checks. Natural-language turn selection/pass behavior remains model-dependent after the host chooses the speaker.

## Remaining boundaries and next improvements

1. **Local privacy and retention:** conversations, handoffs and activity logs remain plaintext in the user's app-data folder. Private question answers are masked and omitted by the host, but providers receive them and may retain or repeat them. Native CLI history, exported files and existing backups are separate copies. A useful next feature is opt-in Windows-protected storage with a tested migration/recovery path and explicit retention settings. No user history was deleted to impose a new retention policy.
2. **Permissions:** AI Hub launches trusted local CLIs and forwards explicit approvals. Their sandbox/tool policies enforce actual access; AI Hub is not a second OS sandbox. Peer text is labeled as context, but labels are not a security boundary against prompt injection. Editing permissions and CLI configuration still matter.
3. **Resource/cost limits:** rendering, frame, request and automatic-round bounds are enforced. A long legitimate tool/model turn can still run until cancelled, and logs can grow over time. Automatic collaboration has no provider-independent token/spend budget. Add visible usage budgets and opt-in log retention as separate product features.
4. **Memory:** per-agent context cursors reduce repeat transmission, while project-status reports reduce duplicate inspection. General task allocation, durable task notes, semantic retrieval and work that survives conversation switches are still later shared-memory milestones. A bounded transcript cannot guarantee permanent model recall.
5. **Release maintenance:** the runtime is now bundled, so schedule advisory checks and runtime rebuilds. AI Hub's executable remains unsigned; code signing and a signed update mechanism are appropriate before distributing it beyond this laptop.

No unresolved reproducible host crash or data-loss defect from the exercised scenarios remains. This statement is limited to the reviewed code and recorded checks, not a claim that all possible defects or security vulnerabilities have been eliminated.
